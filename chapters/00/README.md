## 一、从"模型"到"agent"

**大语言模型(LLM)本身,只会一件事:给它一段文字,它接着往下写一段文字。**

就这么简单。它不会读你的文件、不会跑命令、不会上网、不会记住上一次对话。它是个**极强的"文字续写器"**,但被关在屋里,只能动嘴。

这带来两个天花板:

1. **它不知道训练之后发生的事**(问它今天的天气,它只能瞎编)。
2. **它不能改变世界**(让它"把这个 bug 修了",它只能告诉你怎么修,不能真去改文件)。

**agent 就是给这个"只会动嘴的大脑",装上"手脚"和"反复行动的能力"。**

一个被广泛接受的说法(HuggingFace、Anthropic 等主流课程一致):

> **agent = 一个 LLM + 一组工具 + 一个让它反复"想→做→看结果"的循环。**

- **工具(tools)**:让模型能真的做事的函数——读文件、搜网页、调 API、跑代码。
- **循环(loop)**:让模型不是"答一句就完",而是"做一步、看结果、再决定下一步",直到任务完成。

## 二、一个具体画面

你对一个 coding agent 说:"这个测试为什么挂了,修好它。"

一个**没有**工具和循环的裸模型:只能凭空猜"大概是 X 吧",经常是错的。

一个 **agent** 会这样(想→做→看,反复):

```
想:我得先看看测试报什么错  →  做:运行测试(工具)  →  看:报了 TypeError
想:是这个文件的问题吧      →  做:读那个文件(工具)  →  看:第 12 行确实错了
想:改成这样               →  做:编辑文件(工具)    →  看:再跑测试,绿了
想:完成                   →  给出最终答复,结束
```

**这个"想→做→看→再想"转圈的过程,就是 agent 的本质。** 它比裸模型强大,是因为它能**根据真实世界的反馈来纠正自己**,而不是一次性瞎猜。

## 三、什么时候**不**需要 agent(重要)

主流课程(尤其 Anthropic 的《Building effective agents》)反复强调一点:**别动不动就上 agent。**

- 任务能一步说清、结果可预测(翻译一段话、提取一个字段)→ **一次模型调用就够,别用 agent。**
- 任务是固定流程、步骤写死(先翻译再摘要再存库)→ 用**写死的工作流(workflow)**,别让模型自己决定步骤。
- 只有当任务**开放、多步、事先无法把步骤写死、需要模型自己边做边判断**时 → 才需要 agent。

**记住:agent 更强,但也更慢、更贵、更难预测。能用简单方案就别上 agent。** 判断"该不该用 agent"本身,就是这门课要给你的判断力之一。

## 四、这门课把你带到哪(地图)

你要**从零、亲手**把一个 agent 一块块建起来,全程 provider 中立(不绑任何一家):

> **名词** · **provider(模型提供方)**:提供大模型能力的厂商/服务——OpenAI、Anthropic、Google,
> 以及本地跑的 Ollama 等。各家的接口(API 形状、参数)都不一样。
> **provider 中立** = 你的 agent 代码不写死某一家,换一家只动很小的边界层,核心逻辑不变。
> 这正是你说的"不想被锁定":内核靠通用抽象,某家的私有能力放到可替换的接缝后面。

| 阶段 | 你会建的东西 |
|------|------------|
| **01 循环** | agent 的心脏:model → 工具 → 结果 → model 的 loop(下一章) |
| 02–04 | 让"模型"这一侧可控、可测(事件流、消息结构、可脚本化的测试替身) |
| 05–08 | 接真实模型、给工具定契约、让工具能真的读写文件/跑命令 |
| 09–11 | 有状态、可持久化、能在超长对话里管理上下文 |
| 12–14 | 加载外部能力(MCP)、组装成一个完整运行时、给它做评测 |

> 章节弧线参考了成熟的开源 coding agent 结构,但每一步都用主流、provider 中立的方式重建。

**核心不是"学会调某个 API",而是:每一块你都先能自己做出来,于是将来 AI 替你写这些时,你看得懂、也纠得动。**
