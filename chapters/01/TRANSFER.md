# Chapter 01 · 迁移题(超出本章的进阶)

本章的核心 lab(`runAgent`)已经覆盖了单次/连续/并发/异常/maxSteps。下面这些是**更进一步**、真实 agent 会遇到、但本章测试没要求的变体。做之前**先预测**,写进 [`LOG.md`](./LOG.md);想做就自己加测试来驱动。

## 迁移 1 · 取消 / 中断(abort)

真实场景:用户点了"停止",或任务超时。给 `runAgent` 加一个 `AbortSignal`:
- 预测:signal 应该在**哪几个时机**检查?(每轮问模型前?工具执行前?)
- 一旦 abort,已经产生的工具结果该丢弃还是保留?(回想本章"已发生的事实"——后面章节会正式确立)
- 注意:signal 只能"停止等待",不能强杀一个已经在跑的工具——想清这个边界。

## 迁移 2 · 流式输出(streaming)

现在 `model.step()` 一次性返回完整 Step。真实模型是**逐字流式**吐出的。
- 预测:如果 `step` 改成产出一串增量事件(文本片段、逐步拼起来的工具参数),你的 loop 要怎么变?
- 哪些逻辑(执行工具、配对、终止)其实**不受**流式影响?哪些要改?

## 迁移 3 · 子 agent(agent 调 agent)

让其中一个"工具"本身就是**另一个 runAgent**(一个负责搜索的子 agent)。
- 预测:这会不会让你的 loop 结构变复杂?还是"工具就是个返回字符串的函数"这个抽象刚好扛住了?
- 这题让你体会:一个干净的工具契约,能让 agent **组合**起来。

做完在 [`LOG.md`](./LOG.md) 记:哪个迁移让你对 loop 的边界理解更清楚了?
