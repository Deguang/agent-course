# Chapter 01 · Agent 的心脏:工具与循环

读完这一章,你会有一个**完整、不留洞**的心智模型:一个 agent 从"接到请求"到"给出答复"之间,到底发生了什么。然后你亲手把它写出来(`runAgent`)。

---

## 一、完整图景:agent 是怎么运转的

大语言模型(LLM)本身只会一件事:**给它文字,它接着写文字。** 它不会读文件、不会跑命令、不会上网——它是个被关在小黑屋里的大脑,只能想和说。

那它怎么帮你"读 README 并概括"?靠**三方协作**:

```
你(用户) ──请求──▶ 模型 ──提议调用工具──▶ loop 执行工具 ──结果──▶ 模型 ──▶ 最终答复
                     ▲                                              │
                     └──────────── 把结果喂回去,再问一次 ◀──────────┘
```

- **你(开发者/用户)**:提出请求;并事先准备好一批**工具**(能读文件、能算数的函数),把它们的**说明书**告诉模型。
- **模型**:知道有哪些工具后,它**决定**要不要用、用哪个,然后**提议一次调用**——但它**只提议,从不执行**。
- **loop(你写的代码)**:接住模型的提议,**真去执行**工具,把结果**喂回**给模型,再问它下一步;如此往复,直到模型给出最终答复。

**一句话,本章的支点:模型只会提议,执行永远是 loop 的事。** 这条对任何 provider 都成立——它就是所有 agent(ChatGPT 插件、Claude Code、Cursor)的内核。

> **为什么要亲手写这个 loop?** 以后框架(Vercel AI SDK 等)会替你把它写好、藏起来。正因为你亲手写过,才看得懂框架替你做了什么、出问题时才改得动,而不是把它当黑盒。这门课的做法:**先从零建,再用框架。**

---

## 二、由浅入深:从一个工具,到一个循环

### 第 1 步:一个"工具"就是一个函数

别把"工具"想复杂。它就是个普通函数:给它参数,返回一个字符串结果。

```ts
// 一个最简单的工具:读文件(这里先用假数据)
const read = (args: { path: string }) => `文件 ${args.path} 的内容……`;
```

你把可用的工具收进一张**注册表**——名字 → 函数:

```ts
const tools = {
  read,
  // add: (args) => String(args.a + args.b),  // 想加就加,任意多个
};
```

注册表就是"这个 agent 现在能做哪些事"的全集。**注意:表里只有"名字→函数",没有别的。**

### 第 2 步:让模型"知道"有这些工具

模型看不见你的函数体。每次请求,你要把工具的**说明书(schema)**——名字、干嘛用、要什么参数——**连同对话一起发给模型**。模型据此决定调哪个(**按名字**)。

> 本章为了聚焦 loop,用一个**脚本假模型**替代真实模型(见 `agent.test.ts`),所以这一步被简化掉了(假模型直接吐出写好的调用)。**真实世界这一步真实存在**,后面 provider 章节会实建。现在你只要记得:模型是"被告知工具后才提议"的,不是凭空。

### 第 3 步:单次工具调用(一个完整来回)

这是最小的、会用到工具的一次运行。跑一下看它长什么样:

```bash
npm run demo:01
```

它打印这样一条轨迹(每行标了"谁产生的"):

```
① user            读 README 并概括                    ← 你的请求
② model(提议)     调用 read,args={path:"README"}, id=c1  ← 模型只提议
③ loop(执行)      read 返回:"文件 README 的内容……" (配 id=c1)  ← 你的代码真去执行
④ model(最终)     这是一门 agent 课程                  ← 模型看到结果后收尾
```

四步里三个概念,记牢:

- **提议 vs 执行**:②是模型"说"要调 read;③才是你的 loop"真"去调。中间隔着你的代码。
- **id 配对**:模型在②提议时,给这次调用生成一个编号 `c1`;③回填结果时**必须带上同一个 `c1`**,模型才认得出"这是我那次请求的结果"。(这个 id 由**模型**生成,不在工具注册表里——真实 API 里就是 Anthropic 的 `tool_use.id`、OpenAI 的 `tool_calls[].id`。)
- **喂回去再问**:③之后不是结束——结果喂回,模型被**再问一次**(④),才给最终答复。

### 第 4 步:复杂调用——多个 / 连续工具

真实任务往往不止一次调用。两种情况,你的 loop 都要能扛:

- **连续(跨轮)**:模型先调 `read` A,看完结果再调 `read` B,最后才收尾。轨迹变成
  `user → model → loop → model → loop → model`——模型被问了 **3 次**,工具跑了 **2 次**。
- **并发(同一轮多个)**:模型一次提议两个调用,你的 loop 要把它们都执行、结果都配对喂回。

关键领悟:**正因为"调用几次"事先不知道,你才需要一个循环**——问一步、执行、再问,直到模型说"final"为止。这就是为什么 agent 的核心是 loop,而不是一条写死的流水线。

## 三、你要建的:`runAgent`(练习)

上面的知识给全了。现在轮到你把它变成代码。

打开 `agent.ts`:类型(你的"零件")已备好,你只写底部的 `runAgent`。它**不给你现成算法**——因为"照抄伪代码"学不到东西。但你已经有完整图景了,`runAgent` 上方有 3 个问题(控制流 / 顺序 / 配对)帮你把图景落成结构。

**下手法(别一次写完):**

1. 先读 `agent.test.ts`——它是精确规格,两个测试由易到难。
2. 从最简单的 **"无工具"** 测试起(模型第一次就 final,根本不进循环),只写让它变绿的最少代码。
3. `npm run test:01` → 那条红的("单工具往返")会告诉你下一步该加什么。让红色牵着走,直到全绿。

卡住:告诉 tutor「我试了 X、卡在 Y」,按 `定位→签名→伪代码→局部` 逐级要提示——别直接要完整答案。
