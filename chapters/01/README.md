# Chapter 01 · agent 的心脏:一个 loop

## 这一章要建立的一个念头

先别管代码。想象你雇了一个**很聪明、但被关在小黑屋里的助理**:

- 他脑子很好,能读你给的对话、能想、能决定下一步该干嘛。
- 但他**手脚被绑住**——读不了你电脑上的文件、跑不了任何命令、上不了网。

这就是"模型"(model)。它只能**想和说**,不能**做**。

那它怎么帮你"读 README 并概括"?它自己做不到——所以屋外得有个**跑腿的**,听助理指挥去真正干活。
一共三个角色,别搞混:

> **你(用户)**:"读一下 README,然后概括这个项目。"(发出请求)
> **助理(模型)**:"我读不了文件,请跑腿的去执行 `read`。"(他只能**提议**,不能自己读)
> **跑腿的(loop)**:(真的去读了文件)"这是 read 的结果,内容是……"(它**执行**,并把结果递回给助理)
> **助理(模型)**:(看到内容)"好,这是一门 agent 课程。"(**收尾**,答复你)

注意:执行 `read` 的是**跑腿的(loop)**,不是助理、也不是你。你只负责"提出请求"和"拿到最终答复";
中间那些脏活——真去调工具、把结果喂回给模型——是跑腿的干的。

**这个"跑腿的",就是 agent loop。这一章你要写的,就是它。**
它是所有 agent 的心脏——ChatGPT 插件、Claude Code、Cursor,内核都是这个来回。

## 一句要记住的话

> **模型只会"提议",执行永远是 loop 的事。**

模型说"调用 read",不代表文件被读了——它只是吐出一个**意图**。真去读文件、把结果塞回对话、再叫模型继续的,是你写的 loop。这条对**任何** provider 都成立,所以它是整门课的地基。
